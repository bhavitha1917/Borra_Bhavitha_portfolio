These two lectures gave me a better understanding of Specification-Driven Development (SDD) and how it can make working with AI coding agents more structured. One of my biggest learnings was the shift from vibe coding where we keep prompting an AI until something works, to a more organized architect-to-contractor kind of approach. In SDD, we first clearly define what needs to be built, and only then make sure our AI agent follows those requirements, not just guesses.

I understood the SDD workflow mainly through the ReAct (Reason and Act) pattern. The agent, first grasps the context then plans the required actions, implements them, and finally checks the result against the spec.md file. The MNIST handwritten digit classification exercise helped me get the idea in a practical way. We could state constraints like using only the CPU for training, and also define acceptance criteria ahead of time. I also learned that top-1 accuracy is not always a dependable metric, especially when we have imbalanced datasets. In those cases, metrics like macro F1 are more useful, because they give the same weight to all classes.

The second lecture introduced several features of Claude Code. Commands such as /advisor, which lets us consult more capable models , and /branch, which we can use to experiment with separate Git worktrees, showed me how flexible agentic development can actually be. We also explored custom skills for repetitive workflows, along with concepts like sub-agents, MCP servers , and hooks. These tools made it clear that AI agents can do much more than just generate code—they can connect with external tools, APIs, and even development environments as part of a wider workflow.

Overall, I understood that working code does not necessarily mean that I understand the code. SDD can be very useful for repetitive tasks, but it may struggle with novel algorithms and decisions requiring deeper reasoning. So, I still need to critically evaluate the agent’s output, understand the design decisions. 
The main understanding for me is that AI can make development faster, but I still need to remain actively involved in understanding and validating what it produces.
